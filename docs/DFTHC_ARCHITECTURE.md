# DFTHC 扩展架构

更新：2026-10-23。主训练任务为固定 DFTHC 的查表、alias 选择、轨道旋转、算符执行与清理，交付物为 Python 电路生成器。包按任务、电路、评估三层组织，复用 uncompute 的构造和运行能力。

## 验收级别与 agent 工作约定

| 级别 | 名称 | 使用方式 |
|---|---|---|
| 第二级 | **验证通过** | 精确或抽样路径通过；正常奖励、保存候选、继续搜索与后训练 |
| 第三级 | **科学复核通过** | 额外完成参考数学检查与候选精确等价复核；奖励不变 |

训练报告统一返回 `correctness_status="verified"`、`verification_level=2`、`verification_label="验证通过"`。`evidence` 记录方法和证据；`scientific_review.status` 独立表示 `not_run`、`incomplete` 或 `passed`。复核通过后级别为 3。发现真实反例会撤销通过状态和奖励。

Agent 可以直接继承和优化第二级候选。维护方运行 `scientific-review` 对同一份冻结门流复核，记录参考检查摘要、精确证据和适用合同。

## 任务合同

固定 Hamiltonian、整数 alias 表、轨道角度、精度与填充地址约定。核心定义为

```text
K = A_outer† A_inner† SELECT A_inner A_outer
```

一次提交同时输出 `forward`（K）与 `adjoint`（K†）的完整基本门流。含测量的逆程序单独构造，不能机械倒放。两者可采用不同的查表、分解、测量清理和临时寄存器布局。

| 接口 | 输入与输出 |
|---|---|
| label、term | 原标签和项索引，可相干叠加；核心调用后保留 |
| outer_sigma、inner_sigma | alias 比较字，可相干叠加；调用后保留 |
| spin_inner、spin_outer | 自旋／Majorana 分支选择，可相干叠加；调用后保留 |
| system | 任意 Fock 态，可与外部系统纠缠 |
| outer_success | 外层成功标志，可相干叠加；调用后保留 |
| gradient | 指定相位梯度借用态，保持且与逻辑输出解纠缠；占用计入 Q |
| 其他线 | 初态和末态为零；允许自己选择数量、复用与测量方案 |

冻结参考的 `contract.registers` 给出实际线号，不另造一份手写线号配置。梯度态按小端序为 `2^(-g/2) Σ_y exp(-2πiy/2^g)|y⟩`，位宽 `g=max(angle_bits, uniform_bits)`。评估器从该合同生成各位的精确相位输入条件，支持依赖这个资源态的替代算法；候选不能提供或替换输入假设。任意输入证明仍可作为更强的充分证明，但它在梯度线上发现的反例不直接否定合法资源态上的改写。

完整有限输入域均有定义：外层填充 alias 单元是 `alt=keep=0`；非 SF 的内层单元是零字。不能擅自把填充地址或 success=0 分支当成恒等作用。success=0 分支也保留原参考规定的符号／奇偶相位。

## 固定外围与完整 walk

均匀准备、相位梯度准备与退役、两次反射、QPE 调度位于固定外围。轨道旋转、相位加法器和测量反馈仍在核心内。

设 H_o、H_i 分别为外、内层固定均匀准备，B̃ = H_i† K H_i，则

```text
W = R_in H_o† B̃† R_out B̃ H_o
```

外层 alias 只改变外层标签和对应工作位，与 H_i 和 R_out 对易。上述重组保留 SOS 中间投影的生成元标签；不能把该标签也投影掉。外层 uniform 是 walk 的逻辑寄存器，输出可能非零，不属于待清空的临时位。

`circuits/gadgets/synthesis.py::expand_core_walk` 将两个已验收核心嵌回固定外围，并分别重编号量子工作位和经典记录。该模块化边界每次调用都清空工作位，因此比原共享外层 alias 的 walk 多一组外层查表／清理，完整成本须重新计算。共享调度的完整 walk 为 16,800 T／431 Q。

## 提交与验收

```text
维护方固定任务、参考、精度、裁判和 reward
    → Python 生成器（隔离运行）
    → QPEGEN01：完整 forward / adjoint 门流，证明证据可选
    → 冻结产物、严格解析
    → 独立精确／抽样验收 + 同一门流实际计数
    → 状态、诊断、资源和 reward
```

`CircuitBuilder.submit(gates)` 可以整体替换电路，不要求改写历史或固定模板。也可直接写同样的数据格式。`replace`、`phases`、`reuse` 是可选证据构造器，不是唯一提交方式。候选不能改变输入条件、资源态、受保护线、参考摘要、成本或裁判。

支持的基本门是 H、X、Z、S/S†、T/T†、CX、CZ、整体负号，以及 X 基测量复位 HMR、经典 XOR、经典条件反馈和清零断言。Toffoli 等宏须展开成实际门；断言不会复位量子位。

| 验证后端 | 能力与限制 |
|---|---|
| 完整门流相位证明 | 允许相位搬移和合并，独立比较精确路径相位；无外部经典接口时允许内部记录整体重命名 |
| ROBDD 布尔图与模 8 相位 | 对宽可逆电路验证全部输入；保留前缀推导的仿射关系与常量；支持 7T Toffoli 及其显式伴随、零目标 4T AND 和内部测量清理；节点／工作超限返回 unsupported |
| 精确输入列 | 四线、每侧 128 门；有理分圆数计算，不用浮点容差 |
| 精确逻辑信道 | 四线、128 门、最多六个测量／外部经典输入位；对内部记录求和，保留后续读取的经典输出；不要求内部测量 ID 或每个 Kraus 代表相位相同 |
| PyZX | 最多 32 线、每侧 4,096 无条件门；化简结果及完整精确标量均核查 |
| 宽可逆诊断抽样 | 完整指纹未完成时检查 4,096 个输入，按已知仿射输入关系采样，精确模 8 相位；用于发现反例，不单独授予奖励 |
| 相干信道抽样 | 最多 12 活跃线、8 个测量／外部经典位；精确整数分圆数，枚举全部测量分支 |
| 张量整体精确证明 | 对完整相干入口或区域计算两个映射之差的 Hilbert–Schmidt 范数；保留整体相位、辅助位及全部资源态输出；总线数不设 12／32 线门槛 |
| 张量多项式指纹 | 完整相干映射或含测量反馈的逻辑信道；测量记录在网络内完整求和，不枚举全部分支；支持经典 XOR、条件 H/相位/可逆门和可观察记录 |
| 梯度态代数证明 | ROBDD 验证逻辑输出及精确 dyadic kickback 相位，要求均不依赖梯度基变量；证明归还资源态且与逻辑输出解纠缠 |
| Lean 4.35.0 | 最多 8 线、每侧 256 门的无条件 X/CX、Z/S/T 及其逆、CZ、整体负号；检查所有允许基输入的输出和模 8 相位 |
| 可选组合证据 | local / dynamic / boolean / zx 块、相位和物理辅助位复用；独立验证后还要核对证据对应的完整门流 |

验证参考实现完成数学目标与验证候选等价是两层工作。参考保留独立 Hamiltonian、全地址 alias／符号逻辑和旋转组件检查；小实例还把核心接回 walk，与独立 ladder-operator Hamiltonian 对照。大 Fe₂S₂ 的正确性依据组件验证与组合，不声称做了全态模拟。

各条路径检查候选实际门流。时间按下文的 `staged-v1` 调度分配，生成与验证主体默认共用 600 秒。一次候选的抽样路径最多进行 512 次比较。枚举型相干后端限制分支×状态数为 32,768、单分支 8,192 个振幅和 2,000,000 次状态访问；其容量不足时可继续使用张量路径。

张量路径按中间计算量限制：每次收缩的最大前沿为 16 个二元指标，最多 2,000,000 次分圆系数乘积；图最多 200,000 个指标，精确相位支持到 24 位。系数项和整数长度另设内存界。它可以验证总线数很大而收缩前沿较小的电路，不保证任意高度纠缠电路都在期限内完成。超限返回 `unsupported`，不截断振幅或降低验证标准。候选仍可独立整体提交或附带组合证据。

资源态的局部输入条件来自实际参考前缀：保持可证明的独立相位态，并传播相位门、X 及 X 本征态的受控 kickback；无法继续证明独立性时撤销该局部假设。例如最高梯度位处于 `|−⟩` 时，`CX(a,g)` 可换成 `Z(a)`，展开的 7T `CCX(a,b,g)` 可换成 `CZ(a,b)`。其他梯度位的相干改写由精确分圆张量处理。辅助位清零断言需独立验证，不能充当投影后选择；梯度态输出始终纳入比较，不能靠丢弃借用态获得通过。

## 抽样方法与训练期统计

奖励路径的抽样结论统一为完整映射或信道等价的多项式指纹；不会只因基态抽样未发现错误就授予奖励。基态抽样仍可用于快速排错：完整指纹因计算上限未完成时，宽可逆诊断检查 4,096 个输入的输出比特、精确模 8 相位和内部测量相位债务。发现反例可以否决目标，没有反例仍表示验证未完成，由调度器继续尝试证据与分块。

基态诊断保留前缀的仿射关系：多条线复制同一输入时采样同一个变量，固定为一的位保持为一，并加入零变量赋值锚点。单独的基态随机测试可能漏掉罕见输入上的错误，因此不把它的均匀错误质量界当作完整任务误收概率。这一区分使奖励不再鼓励删除罕见分支；无需候选提交者缩小电路改写范围或提供形式化证明。

前缀经过尚未解析的 H 或反馈后，未知输入符号只提供一个包含真实输入的集合，不能据此假设局部输入服从均匀分布。这类块继续使用精确或完整映射/信道验证，或尝试其他分块；不会据其独立基态样本判断真实输入上的错误比例。同一命题已经发现反例时，调度器保留该结果，不因精确预算耗尽而再次用抽样尝试通过；局部反例仍只否定这个分块目标。

枚举型相干后端计算随机指纹 `u† E(|v><w|) z`，其中四个向量的实部／虚部独立取随机整数。实际计算为 `Σ_m (u†K_m v) conjugate(z†K_m w)`，完整求和测量分支及其未归一化 Kraus 权重；经典输出按记录值分别比较。不同信道的差异构成次数至多 4 的非零多项式。应用 [Schwartz 的多项式恒等测试界](https://doi.org/10.1145/322217.322225)，每轮误收概率至多 `4/2^b`，b 默认 32；有清零断言时采用更宽松的次数上界。重复轮数根据分配的 alpha 自动确定。计算使用精确整数分圆数与二的幂分母，没有浮点容差或振幅截断。该概率界针对完整信道等价。

张量指纹将边界向量写成随机乘积形式，各因子为 `(1, a+ib)`。这是完整映射／信道的多项式恒等测试：乘积向量张成整个允许输入和输出空间，因此某个罕见基输入上的错误仍对应非零多项式，不按该输入的出现频率寻找反例。若有 m 个仿射输入变量、n 个输出量子位、c 个外部经典位与可观察输出记录，映射比较次数界取 `max(m+n, 2m, 1)`，信道比较取 `max(2(m+n)+c, 1)`。两侧清零断言还比较有／无断言的总迹，拒绝丢失振幅；总误收界保守取 `3(d/2^b)^r`。b 与轮数 r 由本次预算确定，证据保存实际值。相位使用 `Q[ζ_(2^g)]` 的精确稀疏系数，没有浮点误差窗口。独立前缀的任意相干输入、与外部系统的纠缠、测量反馈和梯度归还均包含在命题中。

张量网络作为电路等价表示可参考[张量算符等价检查研究](https://arxiv.org/abs/2410.10946)；多项式指纹的次数界使用上述 Schwartz–Zippel 定理。本项目的计算核是现有 `circuits/sim.py` 内的精确实现，不使用近似张量截断结果来授予奖励。

候选门流冻结后，由维护方生成新的 256 位随机种子，并用 SHAKE-256 展开测试值。统计界以独立随机抽样模型为基础；实现采用密码学伪随机数。学习端不获取种子，也不能设置样本数或测试策略。

`runs/training-ledger.sqlite3` 以原子事务分配第 i 次已冻结产物的尝试，包含验证失败和重复提交；置信预算 `alpha_i=10^-9/[i(i+1)]`。第 j 次内部比较再分配 `alpha_ij=alpha_i/[j(j+1)]`。两层预算求和不超过 10^-9，适用于固定产物之后的新随机测试及自适应提交，约束这些完整目标指纹的误收概率。这里仍依赖实现正确和独立随机模型；实现采用密码学伪随机数。连续训练保留账本，重启和更换 bundle 不重置编号。生成器在冻结前失败不产生抽样查询，但计入会话提交预算。

报告保存尝试编号、种子承诺、门流摘要、每块方法、样本数、次数／轮数及预算。宿主 `sampling-private.json` 保留复查所需种子；它不挂载到生成器沙箱。

## 成本与奖励

主任务一次包含正向和伴随各一次，指标为

```text
T = T_forward + T_adjoint
Q = 两个入口实际触及的物理线与受保护接口线的并集大小
C = T × Q
reward = C0 / (C0 + C)；未通过为 0
```

物理线是两次调用共用的固定分配池，编号可不连续。不同 ID 不自动视作可复用；若要减少 Q，需要在实际门流中使用同一条线并证明工作空间满足条件。相位梯度占用计入 Q，外围准备门不混入核心 T。

参考与结构化候选采用相同的 7T 展开、复位后可证零目标 4T AND 和精确相位合并规则。结构层另报参考的 Toffoli 数；任意 Clifford+T 门流不把 T/7 冒充 Toffoli。硬件运行时间不从 TQ 直接推导。

`reference_error_bound` 是冻结参考的综合误差：核心为零，表示参考本身已经离散化；抽样证据中的统计界单列。外围资源态综合和 Hamiltonian 量化另有各自误差预算。

```text
src/qpe_lab/
├── __init__.py                  公开生成器接口
├── __main__.py / cli.py         命令行流程
├── contracts.py                共享任务规格、验证目标、后端结果
├── tasks/
│   ├── task.py                 读取和校验固定任务
│   ├── bundle.py               输入封装、摘要、冻结和加载
│   ├── prompt.py               任务说明、DSL、目标和提交上下文
│   └── data/                   因子、角度和 Hamiltonian 数据准备
├── circuits/
│   ├── builder.py / ops.py      构造器、门定义和产物格式
│   ├── gadgets/                查表、准备、旋转、SELECT 和综合
│   ├── checks.py               构造和验收共用的纯电路检查
│   ├── sim.py                  精确与抽样计算内核
│   └── compact_reader.py       上游 OPSTRM01 适配
└── evaluation/
    ├── session.py              隔离工具、会话预算、起点复现和最佳结果管理
    ├── protocol.py / sandbox.py 执行、验收编排、报告和科学复核
    ├── cost.py                 双入口成本、奖励和结果解释
    ├── walk.py / rotation.py   参考数学和组件任务验收
    ├── kernel.py               上游 C 内核交叉检查
    └── verification/
        ├── engine.py           目标、分块、组合、预算、缓存和后端注册
        ├── exact.py            单个目标的精确等价证明
        ├── sampled.py          单个目标的抽样、随机挑战和持续训练账本
        └── lean.py             可信命题生成与 Lean comparator 检查
```

| 位置 | 职责 |
|---|---|
| 任务层 | 给出优化对象、参考与运行上下文；不判候选、不发奖励 |
| 电路层 | 表达、构造、变换和执行电路语义；不读取训练账本或奖励策略 |
| 评估层 | 运行候选、建立等价证据、统计实际资源、计算奖励并保存报告 |
| 共享合同 | 任务数据结构、`VerificationGoal`、`VerificationResult`；不导入三层业务代码 |

依赖方向为：任务层 → 电路层，评估层 → 任务层与电路层；各层可读取共享合同。电路层不反向导入任务层或评估层，任务层不导入评估层。原先构造器调用评估器中的查表、相位与零目标检查，现已统一放到 `circuits/checks.py`。基础门计数也在这里，评估层负责组合成本与 reward 策略。

参考冻结由 `evaluation/protocol.py::freeze_training` 编排：任务层准备输入 → 电路层构造 → 评估层检查参考 → 任务层封存。Agent 任务出口是 `tasks/prompt.py::agent_task`：从同一份冻结合同和门定义生成本轮上下文，不重新编译参考。

`evaluation/session.py` 提供维护方启动的会话工具边界：只暴露任务、允许的文件、隔离 Python 实验、正式提交和最佳产物。它复用任务派发、生成器沙箱和评估协议，不实现另一套验证器或奖励规则。会话预算在实际执行前持久化，进程锁禁止同一路径并发消费；重启不返还次数、不延后截止时间。最佳记录来自绑定同一 bundle 的验收结果，读取时核对实际源码与门流。模型启动器只转发会话工具，不给模型独立的宿主文件/执行权限。

候选流程为 `protocol.py → sandbox.py → verification/engine.py → 后端 → engine.py 汇总 → cost.py → report.json`。自动分块和组合只在 `engine.py` 中实现；后端只回答收到的目标。Agent 仍可独立重写完整电路。

调度由 `engine.py::verify_entry` 和冻结 `verification.schedule` 管理：短时整体精确探测 → 可选变换证据 → 分块规划与局部精确 → 完整精确搜索 → 整体抽样 → 混合分块。精确路径能完成时不运行抽样；混合路径可让不同块分别采用精确、Lean 或抽样。局部划分未证明成功时继续其他路径；完整目标的反例终止验收。任何阶段超时都不能转为通过。

默认配置 `staged-v1` 给整体探测 2 秒、证据核验 10 秒、每次证据绑定／分块规划 3 秒、局部精确 15 秒。短入口预算按比例缩小这些探测窗口。完整精确搜索保留原有 60 秒，并可使用未消耗的精确探测预算；短总期限下，精确搜索最多使用当时剩余时间的 40%，为抽样保留空间。随后整体抽样最多使用剩余时间的一半，其余留给混合分块。精确专用任务不预留抽样窗口。阶段计时涵盖分块、接口推导和证明组合，嵌套后端计时保留外层期限。

`protocol.py` 在每个入口开始时，将剩余验证时间扣除 2 秒收尾预留后，除以尚未验证的入口数；提前完成的时间自动进入下一入口的可用预算。生成与验证主体合计默认 600 秒，并受会话剩余时间约束。输入加载、源码快照、最终记录等外围工作也单独计入端到端耗时，因此 600 秒不是整个工具调用的严格服务时限。阶段窗口决定搜索调度，不改变电路语义、允许的改写类型、输入条件或验收概率界。

`sandbox.py::run_job` 约每两秒发出一次等待反馈；`protocol.py::EvaluationProgress` 只公开入口、阶段、后端名称、耗时与剩余预算，不转发候选日志、测试种子和随机挑战。进度写入运行目录的 `progress.jsonl`；最终报告含 `timing`、逐入口 `verification_schedule` 和逐后端尝试耗时。采样未完成仍可走其他组合路径，缓存仍只复用精确证据。

`cost.py::evaluation_feedback` 生成统一的 `training_signal`。正确性监督只给已通过或明确否决的产物打标签，未完成保留空标签；所有正式尝试继续计入会话预算，未通过的即时 reward 仍为零。维护方的 `complete-verification` 对已冻结门流追加一次最多 1,800 秒的验收，完整精确搜索额度随总期限同比放大，其他验收规则不变。补验前核对 bundle、源码及门流摘要，先持久化一次性预约，再分配新的账本挑战；不会再次执行生成器。原报告保存到 `completion/original-report.json`，完成后更新同一个运行记录。补验属于第二级验收，与只走精确后端的第三级 `scientific-review` 分开。

单个抽样目标的路由位于 `sampled.py::SamplingContext`：无测量和经典接口的目标使用保持整体相位的等距映射指纹；含测量反馈的小目标先尝试枚举型完整信道指纹，其余使用张量信道指纹。资源态进入相应张量目标。完整指纹未完成时，可以运行适用的基态诊断查找反例；诊断未发现错误不会转成通过，而是回到调度器尝试其他覆盖方式。多项式指纹通过即可获得第二级奖励，无需等待精确复核。

框架检查每个变化区间和未改间隔，允许插入、删除及跨组件修改。区间输入条件由原参考前缀的仿射支撑推导；`assert_zero` 不增加输入假设。两侧后续读取的测量记录都列入输出条件。没有跨边界经典输入／输出的目标，可按定义顺序统一内部记录编号再做结构证明，完整保留 XOR 与反馈依赖；实际产物、摘要和成本仍使用原门流。逐块证据绑定范围及父目标摘要，只有完整覆盖才产生入口结论。组合证据中的每个阶段同样使用这一条路径。

精确缓存是评估进程内有界缓存，两个入口共用。缓存键包括实际门流、冻结合同、输入／输出条件、语义版本、后端身份与版本；相同命题在另一个位置可复用。抽样结果不进入缓存，每次比较使用新的查询编号和对应统计预算。混合证据逐块记录完整目标的指纹误收界，汇总反馈按目标去重后相加；它不等同于硬件噪声、Hamiltonian 量化或化学能量误差。

公开接口 `from qpe_lab import CircuitBuilder` 等保持一致。内部旧 `evalcore/`、根目录 `builder.py/ops.py/sim.py`、旧 `gadgets/` 和 `data/` 已迁移，不保留两套实现或兼容转发目录。上游固定任务和评估入口仍在 `third_party/uncompute/`。使用方式见 [生成器接口](CIRCUIT_GENERATORS.md)。

## 增加验证后端

后端统一接收 `contracts.py::VerificationGoal`：参考／候选实际门流、冻结参考摘要、仿射输入条件、外部经典输入、可观察经典输出、相位与信道语义、完整入口或区间范围、资源上限和可选证明。`sha256` 绑定本次目标及附件；`statement_sha256` 绑定命题本身，用于精确缓存。返回 `VerificationResult`，包含目标摘要、证据，以及 `proved`、`sampled`、`counterexample`、`unknown`、`error`；未完成原因区分 `unsupported`、`timeout`、`tool_error`。结果不包含 reward。

`engine.py` 的维护方注册表规定后端顺序与保证类型。`unknown` 继续尝试其他后端；完整目标的反例停止验收；只有绑定当前目标的 `proved` 或 `sampled` 才能通过。目标摘要覆盖实际门流、受保护线和辅助位输入条件。科学复核只使用精确后端，训练通过等级与奖励由评估流程统一给出。

新增后端实现 `verify(goal, context) → VerificationResult`，在维护方注册表登记名字、版本、保证类型并加入正反例测试即可。若需要新的证明附件，再扩展 `circuits/ops.py` 的数据格式。后端不能修改目标、替换合同或声明成本。新增后端、语义或判定规则后重新冻结 bundle；持续训练继续使用原账本。

## Lean 证明路径

`lean.py` 从实际门流生成同一份门语义、输入条件和 `QPE.circuit_equivalent` 命题。Agent 提供证明项，例如 `by decide`；框架把它放到生成的定理中。门语义表示 `|x⟩ → exp(iπp/4)|y⟩` 的 `(y,p mod 8)`，逐个允许输入验证后覆盖其任意线性组合及外部纠缠。当前范围不含 H、测量、反馈和断言，遇到这些门返回能力不足，其他后端仍可继续。

使用 [Lean 官方 comparator](https://lean-lang.org/doc/reference/latest/ValidatingProofs/) 独立比较可信命题与证明、重新检查内核并核对公理；只允许标准公理 `propext`、`Quot.sound`、`Classical.choice`，拒绝 `sorryAx` 和额外假设。证明检查运行在隐藏任务文件和训练账本的隔离环境内，工具链内容计入裁判摘要。无效证明不是电路错误的反例。安装和附件写法见 [生成器接口](CIRCUIT_GENERATORS.md#lean-附件)。

默认 `acceptance=exact_or_sampled`，启用的适用后端通过即可获得第二级奖励；默认启用精确与抽样，维护方可在 `freeze-training` 加 `--enable-lean`。启用 Lean 的 bundle 将其运行库、可执行文件和隔离工具内容计入裁判摘要；没有启用时不加载或校验该工具链。`--acceptance lean_required` 自动启用 Lean，并要求它覆盖整个入口，其他后端不能代替。两种配置都使用相同的实际成本和 reward 公式，Lean 通过不会自动提升到第三级。

## 维护权限

训练控制端持有固定 bundle 摘要；学习 agent 只提交 Python 源码，不能自选裁判或 reward 参数。生成和验收是不同进程，裁判不导入候选模块，产物与裁判在发放奖励前再次校验。

部署时将学习 agent 的可写工作区与裁判、bundle、账本和结果目录分开。框架修改及裁判发布由维护方完成，学习 agent 通过提交接口交付候选，并可报告反例。

`agent-task` 生成任务说明，`training-worker` 隔离执行提交的 Python；二者不隔离外部语言模型的宿主工具，也不执行任务 JSON 中的自由文本预算。启动器负责工作区权限、提交次数和停止条件。把完整宿主写权限交给学习 agent 后，提示词中的权限约定不能代替操作系统隔离。
